# 产品零导入器, 迁移走一次性外挂脚本

产品内不做任何导入功能 (Postman collection / OpenAPI / hurl 均不导入). 用户从 hurl 迁移的路径是: 一次性外挂 Python 脚本分析 hurl 脚本并生成本项目数据文件, 用完即弃. 大多数 API 客户端内建导入器, 此决策刻意不随 — 自用场景下导入是一次性事件, 内建导入器的维护成本远超其价值.

## 后果

- 数据格式须"脚本可生成" (结构规整), 且演进责任在读侧向后兼容, 不保证老脚本能再跑.
- 数据格式 v1 即带显式 `version` 字段, 否则未来无法识别老格式批次.
- 转换脚本必须输出未能转换的条目清单, 禁止静默跳过; 转换结果需人工抽查.
- 迷雾区 "OpenAPI 自动转集合" 回访优先级降低: 集合预期从业务现场手建.
