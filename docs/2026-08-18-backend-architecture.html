1全局图景: 谁和谁说话

本节目标: 一张图看清三个进程角色 (浏览器 / FastAPI 服务 / 数据仓库) 和外部世界的边界.

架构只有一条主轴: 所有逻辑住在 FastAPI 服务进程里. SPA 是它托管的静态页面, 通过同源 HTTP + SSE 与它通信; CLI 是纯瘦客户端, 只发 HTTP. 核心库不暴露给任何外壳直接 import — 服务进程是核心库唯一的消费者.

HTTP / 进程内调用 SSE 流式回传 副作用 (写历史)
关键取舍

CLI 不 import 核心库 (Q1=b). 核心库因此只有一个消费者 — FastAPI 服务; 模块间全部是进程内函数调用, 不存在跨进程 relay 协议, 也没有 "两套执行路径分叉" 的风险.

2六个模块: 接口与藏起来的东西

本节目标: 每个模块按 deep module 原则给出 interface (调用者需要知道的一切) 与 implementation (被隐藏的复杂度). 点击展开.

Store — 数据仓库的唯一读写入口
Interface
领域对象进, 领域对象出: 读集合树 / 读请求条目 / 写请求条目 / 读环境(含 secrets 合并) / 读写 .local 状态 / 追加历史.
Implementation 藏什么
YAML 子集解析 (禁锚点, kv 一律字符串), seq 排序与文件名 tiebreak, 目录布局, .gitignore 规则写入, 历史文件的时间戳命名.
被谁用
Resolve (读定义), Engine (写历史), Sync (拿路径做 git 操作).
Resolve — 请求条目 + 环境 → 可执行请求
Interface
输入: 请求条目 + 激活环境名. 输出: 变量已全部代入, 认证与头已合并完毕的可执行请求.
Implementation 藏什么
变量优先级 (集合 < 环境 < secrets), 集合级默认继承 (headers 按名合并, auth 整体覆盖), 动态变量 {{$now}} / {{$uuid}} 现场求值.
被谁用
Engine.
Engine — 可执行请求 → 事件流
Interface
输入: 可执行请求. 输出: 事件流 meta → chunk* → done. 支持取消.
Implementation 藏什么
httpx, 五种认证构造, multipart 文件引用解析 (相对/绝对路径), SSE 接收, 超时与取消. 唯一副作用: 发送即写历史 (委托 Store).
被谁用
Runner, API 层的 POST /execute.
Assert — 响应 + 断言定义 → 结果列表
Interface
纯函数: 输入响应与断言定义, 输出逐条通过/失败及实际值.
Implementation 藏什么
jmespath 取值, 比较符求值, jsonschema 校验. DSL 具体形状由 MILESTONE-06 原型决定, 这里只定模块位置.
被谁用
Engine (执行后校验), Runner.
Runner — 集合 → 批量事件流 + JUnit 报告
Interface
输入: 集合路径与筛选条件. 输出: 聚合事件流; CI 场景产 JUnit XML.
Implementation 藏什么
按 seq 排序遍历, 逐条委托 Engine, 失败汇总; pytest 作为 CI 宿主 (subprocess + JUnit, 方向 C 结论).
被谁用
API 层的 POST /collections/{x}/run.
Sync — git 绑定 / 提交 / 推拉封装
Interface
绑定远端 / 查看状态 / 提交并推送 / 拉取. SPA 的 git 入口全部经此.
Implementation 藏什么
git 子进程调用, .gitignore 自动写入 (secrets / .local), 冲突报错透传.
被谁用
API 层的 /git/* 端点. CLI 不接管 git (既定约束).

3一次发送的完整旅程

本节目标: 用一条具体请求把图 1 的箭头全部走一遍, 钉死抽象.

请求条目 collections/billing/create-order.yaml:

version: 1
name: 创建订单
method: POST
url: "{{host}}/api/orders"
headers:
  - { key: "X-Request-Id", value: "{{$uuid}}" }
body:
  type: json
  value: '{ "item": "book", "ts": "{{$now}}" }'
assert:
  - { jmespath: "id", op: "exists" }
  1. SPA 点 "发送" → POST /execute (带 token), 请求体指向该条目.
  2. API 层校验 Host 头与 token, 把参数交给核心库.
  3. Store 读出条目 + _collection.yaml + 激活环境 (.local/state.yaml 指向 dev) + dev.secrets.yaml.
  4. Resolve 代入变量: {{host}} ← 环境覆盖集合; {{$uuid}} / {{$now}} 现场求值; 集合级默认的 Authorization 头并入.
  5. Engine 经 httpx 发出请求, 同时让 Store 开始记历史.
  6. 响应若是 SSE 流: 每个事件包成 chunk 事件, 经 FastAPI 的 SSE 通道逐段推给 SPA 渲染.
  7. 连接关闭后: Assert 跑断言; 聚合文本体落盘到 .local/history/billing/create-order/<时间戳>.yaml; done 事件收尾.
SPA 看到的事件流 (SSE data 行) 
{"type":"meta","status":200,"headers":{...},"elapsed_ms":0}
{"type":"chunk","text":"{\"id\":\"ord_1\"}"}
{"type":"done","elapsed_ms":87,"assert":[{"jmespath":"id","op":"exists","pass":true}]}
边界情形

响应非文本或超大 → 历史只落元信息 (content-type/大小). SSE 未关闭不落盘. multipart 请求历史只落文件引用路径+大小, 不内联文件内容 (MILESTONE-02 D011).

4CLI 路径: 幂等拉起常驻服务

本节目标: 说清 AI 手里的 CLI 如何找到或拉起服务, 拿到凭证, 以及生命周期归谁管.

  1. AI 执行 api-client collections run billing.
  2. CLI 读数据仓库 .local/service.json: 
    { "port": 58123, "token": "…", "pid": 40217 }
  3. 读得到且探活成功 → 直接发请求, 零启动成本; 读不到或连不上 → 拉起服务 (uv run), 等服务写出 service.json 后重读再连. 整个动作幂等: 服务已在跑就什么都不做.
  4. 服务常驻; 关闭是显式动作 (CLI stop 子命令或 SPA 入口), 不做闲置自动回收.
token 的三条通道

SPA: 同源托管页直下注入, 无需存储; CLI: 读 .local/service.json; 浏览器里的恶意网页: 三条路都拿不到 — 这是 Q3 安全组合的关键一环 (Host 白名单防 rebinding, token 覆盖读/写/WS 三面).
